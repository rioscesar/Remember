# Contributing

## Development workflow

1. Create a focused branch for each change.
2. Keep the Android project buildable and add tests for changed behavior.
3. Update the relevant documentation when user-facing behavior or architecture changes.
4. Use clear, imperative commit messages.

## Code conventions

- Write production code in Kotlin.
- Follow Android Studio's Kotlin formatting conventions.
- Keep Android resources in `app/src/main/res` and use descriptive names.
- Do not commit local SDK configuration, generated build output, or signing keys.
